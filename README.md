# pr-axis KB API

Knowledge base API for the Ask Marcus chatbot on pr-axisdev.com. Built by Marcus, praxis-ephemeris pattern: public GETs, key-authenticated writes, health endpoint.

## Endpoints

Base URL: the Vercel deployment URL of this project (expected form `https://pr-axis-kb-api-matanguihanbensons-projects.vercel.app`).

| Method | Path | Auth | Description |
| --- | --- | --- | --- |
| GET | `/api/health` | none | Returns `{"ok": true}`. Proves the API is up. |
| GET | `/api/kb` | none | List all entries as `{ "entries": [ ... ] }`. Optional `?topic=<topic>` (services, packages, pricing-rules, custom-builds, process, faqs) and `?q=<keywords>` (keyword search). |
| GET | `/api/kb/:id` | none | One entry by id, for example `service-brand-design`. A missing entry returns 404 with `{"status": "not_ready"}`. |
| POST | `/api/kb` | `X-KB-Key` header | Create or update one entry (upsert by id). Body: `{ "id", "topic", "keywords": [], "title", "answer", "source" }`. Returns the stored entry plus `commit_sha`. |
| DELETE | `/api/kb/:id` | `X-KB-Key` header | Remove one entry. Returns `{ "deleted": "<id>", "commit_sha": "..." }`. |

## Entry shape

```json
{
  "id": "service-brand-design",
  "topic": "services",
  "keywords": ["logo", "brand", "brand design"],
  "title": "Brand Design",
  "answer": "...",
  "source": "services-draft §2",
  "updated_at": "2026-11-27T00:00:00Z"
}
```

The `source` field names the spec the entry traces to. Every entry must trace to the services draft, the landing page spec, or the Ask Marcus spec. Nothing is invented.

## Storage

JSON files in the repo under `data/kb/`, one file per topic: `services`, `packages`, `pricing-rules`, `custom-builds`, `process`, `faqs`. The files are the single source of truth. Reads serve the files (bundled at build time).

Writes (POST and DELETE) commit the change to the repo through the GitHub API, using the `GH_KB_WRITE_TOKEN` env var. The change goes live after the Vercel redeploy, about 1 to 2 minutes. Until the GitHub write token is configured, POST and DELETE return 503 `{"error": "kb write is not configured"}`.

## Environment variables (Vercel, Production + Preview)

| Variable | Purpose |
| --- | --- |
| `KB_API_KEY` | Write key, sent as the `X-KB-Key` header. Generated by Marcus at deploy time. Server-side only, never in code or chat. |
| `GH_KB_WRITE_TOKEN` | Fine-grained GitHub PAT with contents write for `matanguihanbenson/pr-axis-kb-api` only. Set by riv. Until it is set, writes return 503. |

Local development uses a `.env.local` file in the repo root (see `.env.example`). `.env.local` is never committed.

## Errors

- 401 `{"error": "unauthorized"}`: the `X-KB-Key` header is missing or wrong.
- 404 `{"status": "not_ready"}`: the entry does not exist. This is the waiting state, not an error to retry.
- 400 `{"error": "..."}`: bad topic, bad id, or a missing field in the POST body.
- 502: the GitHub API call failed (read or write).
- 503 `{"error": "kb write is not configured"}`: `KB_API_KEY` or `GH_KB_WRITE_TOKEN` is not set in the Vercel project.

## Stack

Next.js 15, App Router, TypeScript, Vercel. No database, no Vercel Blob, no Cloudflare R2.
